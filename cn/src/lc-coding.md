# <a name="coding"></a> 通用编程面试（算法与数据结构） :computer:

通常希望机器学习工程师对软件工程基础有扎实的理解，尤其是算法、数据结构、复杂度分析，以及编写正确、可读代码的能力。

具体会有几轮这类面试，取决于公司和职级。通常，面试流程里会包含一到两轮通用编程面试。这些轮次与软件工程岗位的编程面试类似。面试官通常会评估你是否能够：

- 澄清表述不明确的问题，并明确说明自己的假设
- 选择合适的数据结构与算法
- 解释时间复杂度和空间复杂度
- 将初始解法优化为更高效的方案
- 在不过度依赖 IDE 的情况下，写出可读、可测试的代码
- 清晰表达自己的思路，并测试边界情况

## 准备方法

准备时应按模式来组织，而不是死记零散的题解：

1. 学习核心数据结构，以及每种模式对应的识别信号。
2. 挑选一小组有代表性的题目，并完整理解其解法。
3. 反复复习做错的题，直到你能独立推导出解法。
4. 混合不同模式练习，不要让题型被提前暴露。
5. 最后进行限时、面试风格的练习，以及面向目标公司的题集训练。

对于每次练习：

- **将每道题的时间控制在约 15-20 分钟。** 如果卡住了，就先学习题解，给题目标记待复习，并在 48 小时内不看答案重新做一遍。
- **用表格记录你的练习情况：** 题目、模式、难度、状态（已解决或重做）以及耗时。利用这些结果识别薄弱模式，供后续复习和限时 mock 面试使用。
- **优先关注质量，而不是单纯刷题数量。** 与其做完 400 道只理解一半的题，不如真正掌握 300 道、并且对模式有很强的回忆能力。建议将这部分练习与[第 2 章：ML Coding](./MLC/ml-coding.md)结合起来，这样两种编程面试形式都能覆盖到。

## LeetCode 刷题数量与难度

[LeetCode](https://leetcode.com/) 仍然是准备编程面试最有用的平台之一。我自己大约练了 350 道题。一个合理的目标是 **300-400 道经过充分复盘的题目**，其中 **约 350 道** 可以作为一个很强的参考基准。复盘质量比单纯追求题量更重要。

| 目标总量 | 简单（35%） | 中等（55%） | 困难（15%*） |
| ---: | ---: | ---: | ---: |
| 300 | ~105 | ~165 | ~45 |
| **350（推荐）** | **~120** | **~190** | **~50** |
| 400 | ~140 | ~220 | ~60 |

\* 35/55/15 的比例加总约为 105%，因此这些数量应视为方向性建议，而不是精确配额。大多数准备应以中等题为核心；简单题用于建立熟练度，困难题则用于深化与你目标岗位相关的模式理解。

你可以在[My Leet Sheet](https://docs.google.com/spreadsheets/d/1Ry_JLeOp1fw9mSbbp4ji5l3CZNiCwf8Atevpp0YML6E/edit?usp=sharing)中查看我练过的一些题目示例。

## 核心编程模式

| 模式重点 | 常见识别信号与技巧 |
| --- | --- |
| 数组、字符串与哈希 | 频次统计、查找表、前缀和、排序 |
| 双指针与滑动窗口 | 连续区间、数对、去重、窗口扩张或收缩 |
| 栈与单调栈 | 分隔符匹配、下一个更大元素、表达式求值 |
| 二分查找 | 有序数据、答案空间单调、边界定位 |
| 链表 | 指针操作、快慢指针、反转、环检测 |
| 区间 | 合并、重叠、调度、扫描线 |
| 树（BFS、DFS、BST） | 遍历、递归、路径问题、有序性质 |
| Trie、堆与优先队列 | 前缀查找、top-k、流式最小值或最大值 |
| 回溯 | 组合、排列、子集、约束搜索 |
| 图 | 矩阵遍历、BFS/DFS、拓扑排序、并查集 |
| 进阶图算法与贪心 | 最短路径、最小生成树、局部最优选择 |
| 一维动态规划 | 序列上的状态转移、选或不选决策 |
| 二维动态规划 | 网格、双序列问题、多变量状态 |
| 数学、几何与位运算 | 不变量、坐标、掩码、XOR、按位状态 |

不要只按分块方式分别练这些模式。一旦基础稳定，就应使用混合题集，这样你必须根据题目描述自行识别模式。

## 面向目标公司的练习与限时训练

- 针对目标公司使用带公司标签的题目，重点关注**最近 6-12 个月**被提到的问题。
- 优先练习反复出现的模式和高频被报告的问题，而不是只出现过一次的题目。
- 按目标公司的预期形式练习：固定时间、无提示，并根据要求选择可执行代码或白板风格代码。
- 做混合式限时 mock，而不是提前指定一个已知主题。
- 每次 mock 后，将失误归类为模式识别、实现、复杂度、沟通或测试问题，然后重做最薄弱的部分。
- 不要死记公司标签题的答案。你应该能够解释为什么这种方法有效，并且在约束变化时进行调整。

## 面试过程中

1. 先复述题目，并澄清输入、输出、约束条件和边界情况。
2. 在优化之前，先说明一个正确的基线解法，除非最优方案一眼就很明确。
3. 在编码之前，先解释你选择的数据结构、算法和复杂度。
4. 分小步编写，并确保面试官始终了解你的进展。
5. 测试常规情况、边界、空输入、重复值和失败场景。
