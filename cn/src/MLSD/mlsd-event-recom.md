# 设计一个活动推荐系统

## 1. 问题定义

* 澄清性问题
  - 使用场景？
    - 类似Eventbrite的活动推荐系统。
  - 主要业务目标是什么？
    - 提高售票量
  - 是否需要对用户做个性化？需要面向用户个性化
  - 用户位置？全球（多语言）
  - 用户年龄段：
  - 用户规模？1亿DAU
  - 活动规模？每月100万个活动
  - 延迟要求 - 200毫秒？
  - 数据访问
    - 我们是否有日志并能访问相关数据？能否基于用户交互构建数据集？
    - 我们是否有物品的文本描述？
    - 我们能否使用位置数据（例如第三方API）？（活动是基于地理位置的）
  - 用户能否在平台上加好友？是否要利用好友关系？
  - 用户能否邀请朋友？
  - 用户可以RSVP还是只能注册？
  - 免费还是付费？两者都有

* 机器学习问题建模
  * 机器学习目标：向用户推荐最相关（需定义）的活动，以最大化活动注册数
  * 机器学习类别：推荐系统（排序方法）
    * 基于规则的系统
    * 基于嵌入向量的方法（协同过滤和基于内容）
    * 排序问题（LTR）
      * pointwise、pairwise、listwise
    * 这里选择pointwise的LTR排序建模
  * 输入/输出：输入：`user_id`，输出：排序后的活动列表 + 相关性分数
    * Pointwise LTR分类器输入/输出：输入：`<user_id, event_id>`，输出：`P(event register)`（二分类）

## 2. 指标（离线和在线）

* 离线：
    * precision@k、recall@k（不考虑排序质量）
    * MRR、mAP、nDCG（分别适用于关注首个结果、二值相关性、非二值相关性）-> 这里活动注册是二值相关性，所以使用mAP

* 在线：
    * CTR、转化率、收藏/点赞率、收入提升

## 3. 架构组件（MVP逻辑）
* 采用两阶段（漏斗式）架构，用于
  * 候选生成
    * 基于规则的活动过滤（例如位置等）
  * 排序建模（pointwise LTR）二分类器

## 5. 特征工程

* 注意：活动推荐比电影/视频推荐更有挑战：
   * 活动生命周期短 -> 历史交互不多 -> 冷启动（持续有新物品问题）
   * 因此我们会在特征工程上投入更多精力（构造更多有意义的特征）

* 特征：
  - 用户特征
    - 年龄（one-hot）、性别（分桶）、活动历史

  - 活动特征
    - 价格、注册人数
    - 时间（活动时间、时长、剩余时间）
    - 位置（城市、国家、可达性）
    - 描述
    - 主办方（及其热度）

  - 用户-活动交叉特征
    - 活动价格相似度
    - 活动描述相似度
    - 注册人数相似度
    - 是否同城、同州、同国家
    - 距离
    - 时间相似度（活动时长、星期几、一天中的时间段）

  - 社交特征
    - 参加活动的好友数量/占比
    - 是否由好友邀请（数量）
    - 是否由好友主办（相似性）

  - 上下文
    - 位置、时间

* 特征预处理
  - one-hot（性别）
  - 分桶 + one-hot（年龄、距离、时间）

* 特征处理
  * Batch（用于静态特征）vs Online（流式，用于动态特征）处理
  * 高效的特征计算（例如位置、距离）
  * 改进：为用户和活动学习嵌入向量

## 6. 模型开发与离线评估

* 模型选择
  * 二分类问题：
    * LR（非线性交互）
    * GBDT（适合结构化数据，但不适合持续学习）
    * NN（支持持续学习、表达能力强、适合非线性关系）
  * 可以先用GBDT作为基线模型，再通过NN做改进实验（两者都是不错的选择）
* 数据集
  * 对每个用户和活动pair，计算特征；若注册则标签为1，否则为0
  * 类别不平衡
    * 重采样
    * 使用focal loss或class-balanced loss

## 7. 预测服务
* 候选生成
  * 活动过滤（从百万级缩小到百级）
    * 基于规则（给定一个用户，按位置、类型等做过滤）
* 排序
  * 对`<usr, event>` pair计算分数，并排序
