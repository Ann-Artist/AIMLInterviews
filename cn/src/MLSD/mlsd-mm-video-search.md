# 多模态视频搜索系统

### 1. 问题定义
* 澄清性问题
    - 搜索系统的主要（业务）目标是什么？
    - 具体的使用场景和应用方式是什么？
    - 系统要求是什么（如响应时间、准确性、可扩展性，以及与现有系统或平台的集成要求）？
    - 从数据规模和用户交互量来看，系统的预期规模有多大？
    - 是否有可用数据？是什么格式？
    - 能否使用视频元数据？可以
    - 是否需要个性化？不需要
    - 需要支持多少种语言？

* 用例与业务目标
  * 用例：用户在搜索框中输入文本查询，系统展示最相关的视频
  * 业务目标：提升点击率、观看时长等
* 需求
  * 响应时间、准确性、可扩展性（5000万DAU）
* 约束
  * 预算限制、硬件限制，或法律与隐私约束
* 数据：来源与可用性
  * 来源：视频（10亿）、文本
  * 1000万个`<video, text_query>`样本对。视频包含文本格式的元数据（标题、描述、标签）
* 假设
* 机器学习问题表述：
  * 机器学习目标：检索与文本查询相关的视频
  * 机器学习输入/输出：输入：用户的文本查询；输出：视频分享平台上的相关视频排序列表
  * 机器学习类别：视觉搜索 + 文本搜索系统


### 2. 指标
- 离线
  - Precision@k、mAP、Recall@k、MRR
  - 由于评估数据的格式是`<video, text>`对，我们选择MRR（结果中首个相关元素排名的平均值）
- 在线
  - CTR：问题在于不能直接衡量相关性，且容易受到标题党影响
  - 视频完播率：用户即使只观看了一部分，仍可能认为视频是相关的
  - 总观看时长
  - 我们选择总观看时长：它是相关性的较好指标

### 3. 架构组件
面向文本查询的视频内容多模态搜索（视频、文本）：
- 视觉搜索系统
  - 文本查询 -> 视频（基于文本与视觉内容的相似度）
  - 双塔嵌入架构（video和text_query编码器）
- 文本搜索系统
  - 基于文本查询搜索最相似的标题、描述和标签
  - 可以使用倒排索引（如Elasticsearch）来高效执行全文搜索
    - 倒排索引是一种将词项（单词）映射到其出现的文档或位置的数据结构，可实现高效的基于文本的文档检索，常用于搜索引擎。

### 4. 数据采集与准备
我们使用已提供的标注数据，格式为`<video_id, query>`。

### 5. 特征工程
- 非结构化数据预处理
  - 文本预处理：归一化、分词、token转为ID
  - 视频预处理：解码为帧 -> 采样 -> 调整尺寸 -> 缩放、归一化、颜色校正

### 6. 模型开发与离线评估
* 模型选择
  - 文本编码器：
    - Text -> Vector（Embeddings）
    - 两种方法：
      - 统计方法（BoW、TF-IDF）
      - 机器学习编码器（word2vec、基于transformer的模型，如BERT）
    - 我们选择基于transformer的模型（BERT）。

  - 视频编码器：
    - 视频级
      - 成本更高，但能捕获时序理解
      - 示例：ViViT（Video Vision Transformer）
    - 帧级（从采样帧中提取并聚合）
      - 成本更低（训练与服务速度、算力消耗）
      - 示例：ViT


* 模型训练
  - 对比学习（类似视觉搜索系统）。

### 7. 预测服务
组件：
- 基于文本查询的视觉搜索
  - text -> preprocess -> encoder -> embedding
  - 视频通过其编码后的嵌入向量建立索引
  - 搜索：使用近似最近邻搜索（ANN）
- 文本搜索
  - 使用Elasticsearch（全文 / 模糊搜索）
- 融合
  - 基于相关性分数加权求和进行重排序
  - 使用模型进行重排序
- 重排序
  - 业务层逻辑与策略
