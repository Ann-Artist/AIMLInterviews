## 3. 架构组件（MVP 逻辑）
个性化推荐系统常见的主要方法： 
* 基于内容的过滤：推荐与用户认为相关（如点赞）的物品相似的内容
    * 不需要交互数据，也能向用户推荐新物品（无物品冷启动问题）
    * 能捕捉用户独特兴趣
    * 但存在新用户冷启动问题
    * 需要领域知识
* 协同过滤（CF）：基于用户-用户相似度（user-based CF）或物品-物品相似度（item-based CF）
    * 优点
        * 不需要领域知识
        * 能捕捉新的兴趣方向
        * 比基于内容的方法更快（不需要内容信息）
    * 缺点： 
        * 冷启动问题（用户和物品两侧都有）
        * 对小众兴趣支持不足
* 混合式 
    * 并行混合：combine(CF results, content based)
    * 串行： [CF based] -> Content based

我们怎么选？  
这里选择串行混合模型（例如视频推荐中的标准做法）

为了满足延迟要求，并能将系统扩展到数十亿物品规模，我们采用三阶段推荐系统（漏斗式架构）。

```mermaid
   Candidate generation --> Ranking --> Re-ranking
```

第一阶段使用轻量模型，从数百万物品中检索出数千个候选。
第二阶段（排序）聚焦高精度，使用更强的模型。由于这里只在较小的候选子集上运行，因此对线上服务速度影响不大。 

实际中的候选生成通常来自多个候选生成模型的聚合。这里可以假设有三个候选生成模块： 

1. 候选生成 1（基于相关性）
2. 候选生成 2（基于流行度）
3. 候选生成 3（基于趋势）  

其中，候选生成 1 使用协同过滤。

排序阶段使用基于内容的建模。

## 6. 模型开发与离线评估

### 6.1 候选生成

对于候选生成 1（基于相关性），我们选择协同过滤（CF）。 

对于 CF，有两种基于嵌入向量的建模方案： 
1. 矩阵分解 
   * 优点：训练速度快（只需学习两个矩阵），服务速度快（静态学习得到的嵌入向量）
   * 缺点：只依赖用户-物品交互（无法使用用户画像信息，例如语言）；存在新用户冷启动问题 
2. 双塔神经网络：
   * 优点：可接收用户特征（用户画像 + 用户搜索历史）-> 推荐质量更高；可处理新用户 
   * 缺点：训练成本高，服务速度较慢     

这里我们选择双塔网络。 

#### 双塔网络
  * 两个编码塔（用户塔 + 物品塔）
  * 用户塔将用户特征编码为用户嵌入向量 $u$ 
  * 物品塔将物品特征编码为物品嵌入向量 $v_i$
  * $u$ 与 $v_i$ 的相似度视为相关性分数（将排序视作分类问题）


#### 损失函数：
对每个正样本标签及采样得到的负样本，最小化交叉熵

### 6.2 排序
在排序阶段，我们优先考虑精度而不是效率。这里选择基于内容的过滤，使用依赖物品特征的模型。  
机器学习目标可选： 
   - 最大化 P(play | U, C)
   - 最大化预期总游玩时长
   - 多目标（多任务学习：加入对应损失）
  
模型选项： 
- FF NN（例如与双塔网络类似的结构）+ logistic regression 
- Deep Cross Network（DCN）

特征  

* 游戏 ID 嵌入向量（已玩游戏的平均嵌入向量、已曝光游戏的嵌入向量）
* 游戏历史特征
  * 历史曝光、评价、点赞等数量
  *  时间特征（例如距离上次游玩经过的时间），
* 语言嵌入向量（用户、物品），
* 用户画像 
* 用户历史特征（例如搜索历史）



### 6.3 重排序
根据额外业务规则对物品进行重排序（过滤、提升）  
可以使用机器学习模型识别标题党、有害内容等，也可以使用启发式规则   
示例： 
* 年龄限制过滤 
* 地区限制过滤 
* 内容新鲜度（提升新内容）
* 去重 
* 公平性、偏差等

## 9. 扩展性
前面介绍的三阶段架构——候选生成、排序、重排序——具有良好的可扩展性。它同时满足了速度（漏斗式架构）、精度（排序组件）和多样性（多路候选生成）的要求。 

### 冷启动问题：
* 新用户：双塔架构可以接收新用户，即使没有交互数据，也仍可使用用户画像信息 
* 新物品：先随机推荐给部分用户并收集数据，再用新数据对模型进行微调

### 训练：
我们需要能够对模型进行微调  
### 探索-利用权衡
- 多臂老虎机（一个智能体会重复选择某个选项，并获得回报/代价。目标是在持续学习哪些选项最有价值的同时，最大化长期累计回报。）
### 其他扩展：
* [Multi-task learning](https://daiwk.github.io/assets/youtube-multitask.pdf)
  * 包含一个共享特征提取器，与多个预测头联合训练，每个预测头负责预测用户行为的不同方面，例如点击率、观看时长和观看次数。模型训练结合了监督学习与无监督学习技术，包括交叉熵损失、pairwise ranking loss 和自监督对比学习。
* 位置偏差（检测与校正） 
* 选择偏差（检测与校正）
* 加入负反馈（dislike）
* 局部性保持： 
  * 使用序列化用户行为信息（CBOW 模型）
* 季节性影响 
* 如果我们只有查询以及个性化的（item、provider）历史怎么办？ 
  * item embeddings、provider embeddings、query embeddings 
  * 可以构建 query-aware attention mechanism 来计算
