# 搜索系统

### 1. 问题定义
* 澄清性问题
    - 这是通用搜索引擎（如 Google），还是垂直搜索（如 Amazon 商品搜索）？
    - 搜索系统的首要（业务）目标是什么？
    - 具体的使用场景和落地场景有哪些？
    - 系统要求是什么（如响应时间、准确性、可扩展性，以及与现有系统或平台的集成要求）？
    - 系统在数据规模和用户交互规模上的预期有多大？
    - 是否已有可用数据？是什么格式？
    - 是否需要个性化？不需要
    - 需要支持多少种语言？
    - 平台上有哪些类型的商品（products）？它们具备哪些属性？
    - 用户常见的搜索行为和模式是什么？用户是否经常使用筛选、排序或高级搜索功能？
    - 是否存在该业务场景（电商）特有的搜索挑战？例如如何处理商品可用性、价格和用户评价？

  * 机器学习目标：检索与文本查询最相关的商品
    * 我们可以将相关性定义为点击、成功会话、转化等信号的加权汇总。
  * 机器学习输入/输出：输入：用户的文本查询；输出：电商平台上最相关商品的排序列表

### 2. 指标
- 离线
  - Precision@k、Recall@k、MRR、mAP、NDCG
  - 我们选择NDCG（适用于非二值相关性）
- 在线
  - CTR：问题是不直接反映相关性，且容易被点击诱饵影响
  - 成功会话率：停留时长 > T，或加入购物车
  - 总停留时长
  - 转化率

### 3. 架构组件
* 面向商品内容的多模态搜索（文本、图片、视频），输入为文本查询：
* 多层架构
  * 查询理解 -> 候选生成 -> 第一阶段排序器 -> 第二阶段排序器 -> 混排器 -> 过滤器
* 查询理解
  * 拼写纠错
  * 查询归一化
  * 查询扩展（如添加同义表达）/ 查询放宽（如去掉“good”）
  * 意图/领域分类
* 候选生成
  * 重点关注召回，把百万/十亿级候选缩小到万级
* 排序
  * 基于机器学习
  * 多阶段排序器：如果候选超过1万，或QPS > 1万
  * 10万商品：第一阶段（线性模型）-> 第二阶段（DNN模型）-> 500个商品
* 混排器：
  * 输出SERP（搜索引擎结果页）
  * 将多个来源的结果进行混排，例如文本搜索（倒排索引、语义搜索）、视觉搜索等

#### 检索
* 从100B缩小到100k
* 信息检索（IR）：比较查询文本与文档文本
* 文档类型：
  * 商品标题
  * 商品描述
  * 商品评价
  * 商品类目
* 倒排索引：
  * 一种索引数据结构，将词映射到其在一组文档中的位置（例如 ABC -> 文档1、7）
* 在查询扩展之后（例如将 black pants 扩展为 black 和 pants，或 suit-pants、trousers 等），在倒排索引数据库中搜索并找到相关商品，同时计算相关性分数
* 相关性分数
  * 以下因素的加权线性组合：
    * 词项匹配（如TF-IDF分数）（如 w = 0.5）
    * 商品热度（如评价数或购买数）（如 w = 0.125）
    * 意图匹配分数（如 0.125/2）
    * 领域匹配分数
    * 个性化分数（如年龄、性别、地理位置、兴趣）

### 6. 模型开发与离线评估
#### 排序

* 模型选择
  * 两种选择：
    * Pointwise LTR模型：`<user, item>` -> 相关性分数
      * 可近似看作二分类问题 p(relevant)
    * Pairwise LTR模型：`<user, item1, item2>` -> `item1 score > item2 score ?`
      * 如果预测顺序正确，则损失函数更优
      * 更符合排序本质，但更复杂
  * 多阶段排序
    * 10万商品（关注召回）-> 500个商品（关注精确率）-> 500个商品按正确顺序排列
    * 第一阶段：使用 pointwise LTR -> 二分类器
      * 延迟：微秒级
      * 建议：LR 或小型MART（multiple additive regression trees）
      * 指标使用ROC AUC
    * 第二阶段：Pairwise LTR模型
      * 两种选择（根据训练数据可用性和资源能力决定）：
        * LambdaMART：MART 的一种变体，目标函数改为优化成对排序
        * LambdaRank：基于神经网络的模型，使用 pairwise loss（最小化排序中的逆序对）
      * 指标使用NDCG

* 训练数据集
  * Pointwise 方法
    * 正样本：用户发生交互（如点击、停留时间 > T、加入购物车、购买）
    * 负样本：用户无交互 + 随机负样本，例如来自第10页及之后的结果
    * 每天500万次查询 -> 每个查询取一个正样本和一个负样本 -> 每天1000万个样本
    * 至少使用一整周的数据，以捕捉日常模式
      * 同时捕捉并处理季节性和节假日数据
    * 训练/验证/测试划分：70/30（基于7000万样本）
    * 时间影响：例如使用3周数据：前2/3周用于训练，最后一周用于验证/测试
  * Pairwise 方法：
    * 根据商品之间的相对顺序进行排序，这更接近排序问题的本质
    * 以最小化最终排序结果中的逆序对数量的方式预测文档分数
    * 点式方法的训练数据生成有两种选择
      * 人工标注：每位标注员对10万条查询中的每条查询评估10个结果，10位标注员 = 1000万个样本
        * 成本高，且不可扩展
      * 线上交互数据
        * 为每种交互类型分配分数，例如：
          * 展示但未点击 -> 标签/分数 0
          * 仅点击 -> 分数 1
          * 点击后停留时间 > T -> 分数 2
          * 加入购物车 -> 分数 3
          * 购买 -> 分数 4
