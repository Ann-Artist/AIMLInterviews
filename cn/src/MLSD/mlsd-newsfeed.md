# 信息流系统

### 1. 问题定义
在社交网络平台中展示信息流（来自其他用户的近期帖子和动态）
* 澄清问题
  * 系统的首要业务目标是什么？（提升用户参与度）
  * 我们只展示帖子，还是也展示其他用户的动态？
  * 可用的互动类型有哪些？（点赞、点击、分享、评论、隐藏等）我们要优化哪些互动？
  * 是否也展示广告？
  * 帖子包含哪些类型的数据？（文本、图片、视频）
  * 是否有需要重点考虑的特定用户分群或上下文（例如用户画像特征）？
  * 是否有负反馈特征（如隐藏广告、拉黑等）？
  * 我们可以获取哪些用户-广告交互数据，能否用于训练模型？
  * 是否需要持续训练？
  * 如何收集负样本？（未点击、负反馈）
  * 系统需要多快？
  * 系统规模有多大？
  * 是否需要个性化？需要

* 用例与业务目标
  * 用例：在社交网络平台 App 中，向用户展示好友最容易引发互动的（且尚未看过的）帖子和动态（个性化）
  * 业务目标：最大化用户参与度（作为一组交互行为）

* 需求；
    * 延迟：用户打开/刷新 App 后，200 毫秒内返回刷新后的信息流结果
    * 可扩展性：总用户数 50 亿，DAU 20 亿，每人每天打开 App 两次

* 约束：
    * 隐私与数据保护法规合规。

* 数据：来源与可用性：
    * 数据源包括用户交互日志、广告内容数据、用户画像以及上下文信息。
    * 用于模型训练和评估的历史点击与曝光数据。

* 假设：
    * 用户的参与行为可以通过显式交互（如点赞、点击、分享、评论等）或隐式交互（如停留时长）来表征

* 机器学习建模：
    * 目标：
      * 最大化显式、隐式，或两类反应（加权）
      * 隐式信号：数据更多；显式信号：信号更强，但数据更少 -> 对不同交互进行加权打分：分享 > 评论 > 点赞 > 点击 等
    * 输入/输出：输入：`user_id`，输出：按参与度分数（加权和）排序的、用户未看过的帖子列表
    * 类别：排序问题：可建模为 pointwise LTR，并使用多标签（多任务）分类来解决

### 2. 指标
* 离线
  * ROC AUC（TPR 和 FPR 之间的权衡）
* 在线
  * CTR，
  * 反应率（点赞率、评论率等）
  * 停留时长
  * 用户满意度（调研）

### 3. 架构组件
* 高层架构
  * 可以使用 point-wise learning to rank（LTR）建模方式
  * 多标签/多任务分类的可选方案：
    * 使用 N 个独立分类器（训练和维护成本高）
    * 使用多任务分类器
      * 同时学习多个任务
      * 单个共享层（学习任务间相似性）-> 转换后的特征
      * 任务专属层：分类头
      * 优点：单模型、共享层避免冗余、每个任务的训练数据也可帮助其他任务（适用于数据有限场景）

### 5. 特征工程

* 特征选择
  * 帖子：
    * 文本
    * 图片/视频
    * 反应数量（点赞、分享、回复等）
    * 发布时间长短
    * Hashtag
  * 用户：
    * ID、用户名
    * 人口统计特征（年龄、性别、位置）
    * 上下文（设备、一天中的时间等）
    * 交互历史（如用户点击率、总点击数、点赞数等）
  * 用户-帖子交互：
    * ID（用户、广告）、交互类型、时间、地点
  * 用户-用户（帖子作者）亲和度
    * 关系类型
    * 反应历史（对该作者点赞/评论等的帖子数量）

* 特征表示 / 准备
  * 文本：
    * 使用预训练语言模型获取嵌入向量
    * 这里用 BERT（帖子通常较短，利用上下文感知能力更有帮助）

  * 图片 / 视频：
    * 预处理
    * 使用预训练模型，如 SimCLR / CLIP，将其转换为特征向量

  * 稠密数值特征：
    * 参与度特征（点击次数等）
      * 直接使用 + 做范围缩放
  * 离散数值特征：
    * 年龄：分桶成类别后再做 one-hot
  * Hashtag：
    * 分词、token 转 ID、简单向量化（TF-IDF 或 word2vec）—— 无上下文


### 6. 模型开发与离线评估

* 模型选择
  * 选择神经网络
    * 可处理非结构化数据（文本、图片、视频）
    * 可为类别特征使用嵌入层
    * 可对特征工程中使用的预训练模型做微调
  * 多标签
    * P(click), P(like), P(Share), P(comment)
  * 两种方案：
    * N 个神经网络分类器
    * 多任务神经网络（选择这个）
      * 共享层
      * 分类头（click、like、share、comment）
  * 被动用户问题：
    * 他们所有的 P 都会很小
    * 再增加两个头
      * Dwell time（在帖子上停留的秒数）
      * P(skip)（skip = 停留时间 < t）


* 模型训练
  * 损失函数：
    * L = 各任务 L_i 的求和
    * 对于二分类任务：CE
    * 对于回归任务：MAE、MSE 或 Huber loss
  * 数据集
    * 使用用户特征、帖子特征、交互、标签
    * 标签：每个任务的正负标签（如点赞 / 未点赞等）
      * 对于 dwell time：是一个回归任务
    * 数据集不平衡：对负样本下采样
  * 模型评估与超参数调优
  * 迭代

### 7. 预测服务
* 数据准备 pipeline
  * 静态特征 -> 批量特征计算（每日、每周）-> 特征存储
  * 动态特征：帖子点击数等 _> 流式处理

* 预测 pipeline
  * 两阶段（漏斗式）架构
    * 候选生成 / 检索服务
      * 基于规则
      * 按一定条件过滤并拉取用户未看过的帖子
    * 排序
      * 特征 -> 模型 -> 参与概率 -> 排序
      * 重排序：业务逻辑、额外逻辑与过滤规则（如用户兴趣类别）
* 持续学习 pipeline
  * 用新数据进行微调、评估，如果指标提升则部署

### 10. 其他主题
* 爆款帖子 / 名人帖子
* 新用户（冷启动）
* 位置偏差数据
* 更新频率
* calibration：
  * 对预测概率进行校准，使其与真实点击概率对齐
* data leakage：
  * 测试集或评估集中的信息影响了训练过程
  * 目标泄漏、数据污染（从测试集泄漏到训练集）
* catastrophic forgetting
  * 在新数据上训练后的模型，会丧失此前已学任务上的良好表现
