# 图片搜索系统（Pinterest）

### 1. 问题定义
* 澄清性问题
    - 视觉搜索系统的主要（业务）目标是什么？
    - 它会应用于哪些具体用例和场景？
    - 系统要求是什么（例如响应时间、准确性、可扩展性，以及与现有系统或平台的集成）？
    - 用户将如何与系统交互？（点击、点赞、分享等）？仅点击
    - 系统要搜索哪些类型的视觉内容（图片、视频等）？仅图片
    - 这个系统会部署在哪些特定行业或领域（例如时尚、电商、艺术、工业质检）？
    - 从数据规模和用户交互量来看，系统的预期规模是多少？
    - 是否需要个性化？不需要
    - 可以使用元数据吗？一般来说可以，这里先不使用。
    - 可以假设平台提供的图片都是安全的吗？可以
* 用例与业务目标
  * 用例：给定用户提供的一张查询图片，允许用户搜索视觉上相似的物品
  * 业务目标：提升用户体验、提高点击率、转化率等（取决于具体用例）
* 需求
  * 响应时间、准确性、可扩展性（数十亿张图片）
* 约束
  * 预算限制、硬件限制，或法律与隐私约束
* 数据：来源与可用性
  * 视觉数据来源：用户生成内容、商品目录，还是公开图片数据库？
  * 是否可用？
* 假设
* 机器学习问题定义：
  * 机器学习目标：检索与查询图片在视觉内容上相似的图片
  * 机器学习输入/输出：输入：一张查询图片；输出：与查询图片最相似图片的排序列表
  * 机器学习类别：排序问题（根据物品与查询的相关性对一个集合中的物品进行排序）

### 6. 模型开发与离线评估
* 模型选择
  * 我们选择神经网络（NN），因为：
    * 非结构化数据（图片、文本）-> NN 更擅长处理
    * 需要嵌入向量
  * 架构类型：
    * 基于 CNN，例如 ResNet
    * 基于 Transformer（ViT）
    * 示例：图片 -> 卷积层 -> 全连接层 -> 嵌入向量
* 模型训练
  * 对比学习 -> 用于图片表征学习
    * 训练模型区分相似与不相似的物品（图片）
* 数据集
  * 每个数据点：查询图片、正样本（与 q 相似）、n - 1 个负样本（不相似）
    * 查询图片：随机选择
    * 负样本：随机选择
    * 正样本：人工判断、以交互行为（例如点击）作为代理信号，或基于 q 合成图片（自监督）
      * 人工：成本高、耗时
      * 交互：噪声大且稀疏
      * 人工生成：做数据增强（例如旋转）并作为正样本使用（类似 simCLR 或 MoCo）——与真实场景中的数据分布不同
* 损失函数：对比损失
  * 对比损失：
    * 作用于样本对（Eq, Ei）
    * 计算样本对之间的距离 -> softmax -> 交叉熵 <- 标签
* 模型评估与超参数调优
* 迭代

### 7. 预测服务
* 预测流水线

  * 嵌入生成服务
    * 图片 -> 预处理 -> 生成嵌入向量（机器学习模型）-> 图片嵌入向量
  * 近邻搜索服务
    * 从嵌入空间中检索最相似的图片
      * 精确搜索：O(N.D)
      * 近似搜索（ANN）——次线性，例如 O(D.logN)
        * 基于树的 ANN（例如 R-trees、Kd-trees）
          * 在每个非叶子节点将空间划分为两个（或更多）部分，
          * 只搜索查询 q 所在的分区
        * 局部敏感哈希（LSH）
          * 使用哈希函数将点分到不同桶中（距离近的点分到同一个桶）
        * 基于聚类
    * 我们使用 ANN，并采用现有库，例如 Faiss（Facebook）
  * 重排序服务
    * 业务层逻辑与策略（例如过滤不合适或私密内容、去重等）
* 索引流水线
  * 索引服务：根据图片嵌入向量建立索引
  * 保持表对新图片持续更新
  * 会增加内存使用 -> 使用优化（向量量化 / 乘积量化）
